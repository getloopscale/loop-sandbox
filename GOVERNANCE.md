# Governance

This document describes how decisions are made in LoopSandbox. The project has one maintainer
today. The rules below are written so that they keep working as more maintainers join.

## Roles

A contributor is anyone who opens an issue, reviews a change or sends a pull request.

A maintainer can merge pull requests and cut releases, and is responsible for the direction of the
project, for reviewing contributions and for handling security and Code of Conduct reports. The
maintainers are listed in [MAINTAINERS.md](MAINTAINERS.md).

## How decisions are made

Decisions are made in public, in issues and pull requests.

Most decisions use lazy consensus: a proposal is accepted when no maintainer objects within a
reasonable time. A pull request needs the approval of one maintainer other than its author. While
the project has a single maintainer, that maintainer may merge their own pull requests.

When maintainers disagree and discussion does not settle it, they vote. Each maintainer has one
vote and a simple majority decides. The following changes need a two-thirds majority of all
maintainers:

- adding or removing a maintainer;
- changing this document;
- changing the license or donating the project to a foundation.

## Becoming a maintainer

A contributor can become a maintainer after a sustained record of contributions and reviews that
shows good judgment about the code and the people. An existing maintainer nominates the
contributor in a pull request that edits `MAINTAINERS.md`, and the maintainers vote on it.

The project wants maintainers from more than one organization. No organization has reserved seats.

## Stepping down and removal

A maintainer can step down at any time by opening a pull request that removes their name. A
maintainer who has been inactive for six months, or who has violated the Code of Conduct, can be
removed by a vote of the other maintainers.

## Code of Conduct

The [Code of Conduct](CODE_OF_CONDUCT.md) applies to everyone in the project, maintainers included.
